# GRAM Support

Telegram-поддержка для @valyutaTG_bot через темы группы.

## Как работает

1. Пользователь отправляет `/start`, выбирает «Русский / Українська / English»
   и получает приветствие на выбранном языке. Выбор сохраняется после перезапуска
   и используется в уведомлениях об ошибках и блокировке. Повторный `/start`
   позволяет выбрать язык заново. В приветствии нет рекламной подписи.
2. Первое сообщение создаёт отдельную тему в группе поддержки. Бот публикует
   и закрепляет карточку: имя, username, Telegram ID со ссылкой на профиль,
   bio и `language_code`. В карточке есть кнопка **Ban / Unban**.
3. Последующие сообщения и вложения пользователя копируются в ту же тему.
4. Оператор из `ADMIN_IDS` пишет в теме — сообщение доставляется пользователю.
   Брать обращение в работу или нажимать «Ответить» не нужно.
5. **Ban** прекращает пересылку новых сообщений пользователя в группу.
   Пользователь получает уведомление о блокировке. **Unban** возобновляет
   переписку в той же теме. Операторы могут отвечать из темы и во время блокировки.
   Менять блокировку могут только операторы из `ADMIN_IDS`.

В PostgreSQL хранится только привязка `user_id → group_chat_id + thread_id`
и ID закреплённой карточки с флагом блокировки `is_banned`.
Выбранный язык хранится отдельно в `user_languages`.
Текст сообщений, вложения, bio и история переписки
в базе не сохраняются. Переписка остаётся в Telegram. После перезапуска бот
продолжает использовать существующие темы и блокировки.

## Требования и настройка

- Python **3.11–3.14**; локально и в Docker используется **3.12**.
- [uv](https://docs.astral.sh/uv/getting-started/installation/).
- Docker с Docker Compose.

```bash
cp .env.example .env
```

Если `.env` уже настроен, сохраните его. Обязательные переменные:

- `BOT_TOKEN` — токен бота поддержки.
- `ADMIN_IDS` — Telegram user ID операторов через запятую. Только они могут
  отправлять ответы пользователям из группы.
- `ADMIN_GROUP_ID` — ID супергруппы поддержки с включёнными темами.

Добавьте бота в группу администратором с правами **управлять темами** и
**закреплять сообщения**. При запуске бот проверяет группу и эти права.
Чтобы операторские сообщения доходили боту, он должен оставаться администратором
группы. Сообщения других ботов и служебные события не пересылаются пользователям.

## Docker Compose

```bash
docker compose up -d --build
docker compose logs -f bot
```

Compose запускает PostgreSQL 17, ждёт готовности базы, применяет
`alembic upgrade head` через сервис `migrate`, затем запускает бота.
Данные маршрутизации сохраняются в томе `postgres_data`.

Остановка без удаления данных:

```bash
docker compose down
```

База доступна локально на `127.0.0.1:5433`, в Compose — `postgres:5432`.

## Переход со старой схемы в разработке

Начальная миграция `0001` переписана: вместо таблиц пользователей, тикетов,
сообщений и настроек создаются `support_threads` и `user_languages`.
Новой миграции нет.
Если старая `0001` уже применена, перед запуском новой версии сбросьте базу:

```bash
docker compose down -v
docker compose up -d --build
```

Это удаляет старую локальную базу целиком. Для production такой сброс не предназначен.
Существующие темы в Telegram при сбросе базы не удаляются, но привязки к ним теряются.

## Локальный запуск

```bash
uv sync --locked
docker compose up -d postgres
uv run --locked alembic upgrade head
uv run --locked python -m giveaway_support_bot.main
```

Не запускайте одновременно несколько копий с одним токеном.

## Подключение к PostgreSQL

- `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` — база и реквизиты.
- `POSTGRES_HOST` — локально `localhost`.
- `POSTGRES_PORT` — локально `5433`.
- `DATABASE_URL` — необязательный полный URL для локального запуска, который
  переопределяет `POSTGRES_*`. Спецсимволы пароля в URL должны быть закодированы.
- `LOG_LEVEL` — уровень логирования, по умолчанию `INFO`.

В Compose бот и миграции используют встроенный PostgreSQL с реквизитами
из `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` и адресом `postgres:5432`.

## Миграции

Схема управляется Alembic; подключение хранилища не создаёт таблицы.

```bash
uv run alembic current
uv run alembic upgrade head
```

Для следующих изменений отредактируйте `src/giveaway_support_bot/schema.py`,
создайте миграцию и проверьте результат:

```bash
uv run alembic revision --autogenerate -m "describe schema change"
uv run alembic upgrade head
uv run alembic check
```

## Структура

- `src/giveaway_support_bot/main.py` — запуск и проверка прав бота.
- `handlers_user.py`, `handlers_admin.py` — обмен сообщениями.
- `i18n.py` — приветствия и сообщения об ошибках RU/UK/EN.
- `keyboards.py` — выбор языка и кнопка Ban / Unban.
- `storage.py`, `schema.py` — маршрутизация, блокировки и выбранный язык.
- `alembic.ini`, `migrations/` — схема PostgreSQL.
- `Dockerfile`, `docker-compose.yml` — бот, миграции и база.
